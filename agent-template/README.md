Requires `agents-cli` (`uvx --python 3.13 google-agents-cli setup`; needs Python 3.11+, uv, Node.js). See the harness README.

```bash
agents-cli install && agents-cli lint && uv run pytest
```

`agents-cli lint` runs ruff (check and format), codespell and ty; the `lint` extra in `pyproject.toml` must list all of them. Add `--mypy` to also run mypy (then add `mypy` to the extra).
Python is pinned to 3.13 (`.python-version`, `requires-python <3.14`) so uv does not pick a newer interpreter.

Before any dependent check executes candidate code, `preflight` uses the base revision's scanner
to parse Python, JSON, YAML and TOML, run a local input tripwire over every checkout file, and
check harness policy. It also runs Gitleaks with default rules over the checkout and PR history.
Files must be UTF-8 text, at most 1 MiB, and not symbolic links; unsupported binary assets fail
closed. The input tripwire can report false positives and cannot prove code or dependencies safe.
The workflow itself must be protected by required reviews or an independently enforced trusted
workflow; a PR that can change its own workflow can remove these steps.

The `secret_scan` required check runs Gitleaks over the pull-request commit range, then
`agentic-bootstrap check` for harness framework, residency and required-file rules. The policy check
does not detect secrets. CodeQL and dependency review run on public repositories or when
`GHAS_ENABLED=true` is set after enabling GitHub Code Security. Dependency review also requires the
dependency graph to be enabled. Gitleaks CLI v8.30.1 is installed from its official
release using a verified SHA-256 digest; organisation-level GitHub secret scanning and push protection
remain a TODO pending confirmation of GHAS licensing.

If you created this repo from an activated harness venv, run `deactivate` (or open a new terminal) before `agents-cli install`. Otherwise uv warns that `VIRTUAL_ENV` does not match the project `.venv`. It is harmless: uv ignores the active venv and creates this project's own `.venv`.

## After `agents-cli install`: next steps

Work through these in order. Each step ends with a check you can run.

### 1. Frame the agent (before changing code)
Fill in `docs/mission-brief.md`: purpose, users, data, hosts it calls, human-in-the-loop and approvers. The hypotheses you write there become your eval criteria, and the hosts become egress entries that need approval.

### 2. Replace the example agent
The mechanic/vehicle content is a placeholder. Change these together so they stay consistent:

| What | Where | Notes |
|---|---|---|
| Behaviour and business rules | `agent/prompts.py` | Keep instructions here, not inline, so changes are easy to review and eval. |
| Tools | `agent/tools.py` | Plain functions with type hints and docstrings (ADK uses them to define its tool interface). Return a `status` field and errors as data. Keep them deterministic where possible. |
| Wiring | `agent/agent.py` | Update the `tools=[...]` list. Keep `root_agent`; the model comes from config. |
| Model and region | `agent/config.py` | Set `AGENT_MODEL` in your environment. Only policy-approved regions; never a `global` endpoint. Do not change models or regions without approval. |
| Sample data | `agent/data/` | Remove placeholder data; never commit real customer data. |

For ADK patterns (sub-agents, callbacks, state, memory, approval gates), ask your coding agent to use the `google-agents-cli-adk-code` skill, or see <https://adk.dev>. Use ADK only; do not add another agent framework.

### 3. Add guardrails
Guardrails live at several layers. Use all that apply:
- **Prompt rules** (`agent/prompts.py`): state what the agent must not do, when it must ask for confirmation, and to never invent data.
- **Tool boundary** (`agent/agent.py`, `agent/tools.py`): the starter exposes only service history and repair estimates. It has no booking tool or write integration. If you add a write, enforce trusted, operation-bound approval outside the model and review the service identity's permissions. Prompt instructions and model-supplied confirmation are not authorisation.
- **ADK callbacks** (`before_model_callback`, `before_tool_callback`, etc. on `Agent`): block or rewrite requests and tool calls centrally.
- **Platform controls**: Model Armor settings, egress allowlists, IAM and residency come from the harness policy and `platform_team`. You may only tighten them, never loosen them. Changes to `.github/`, `*.tf`, `*.tfvars` and IAM files need an explicit request and review.
- **Evals**: add a case for every guardrail (see step 5) so a regression is caught.

### 4. Run and debug locally
Authenticate to Google Cloud first (`gcloud auth application-default login`) and set `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION` and `AGENT_MODEL`.

```bash
agents-cli run "Your test prompt"      # one-off smoke test from the terminal
agents-cli run "Your test prompt" -v   # also print full event payloads (tool calls, intermediate steps)
agents-cli playground                  # web UI for interactive conversations
```

Run `agents-cli <command> --help` for the authoritative flags. Treat `run` and `playground` as quick checks only; behaviour is verified by evals, not by single runs.

### 5. Write and run evals
Evals test agent *behaviour* (tool use, answer quality, safety). Unit tests in `tests/` test *code* (tools return the right shape, the agent imports and is wired up). Do not assert on LLM wording in `pytest`.

1. Run `uv run pytest` for credential-free code checks.
2. Follow the [eval guide](evals/README.md) to run the two starter cases in an approved
   non-production project. The guide separates inference and grading regions.
3. Replace the example cases in `tests/eval/datasets/basic-dataset.json` with your own normal
   flows, edge cases, and at least one case per guardrail. Adapt `tests/eval/eval_config.yaml`
   to match. Start small and iterate before adding more cases.
4. The starter marks are 80% coverage and 80% eval quality. The business owner can propose a higher agent-specific mark for review.
5. Do not hand-edit `evals/baseline/`. AI Governance must approve the actual baseline through a reviewed change.

### 6. Keep tests, docs and checks green
Before every PR:

```bash
agents-cli lint && uv run pytest
```

- Before opening a behaviour-changing PR, also run the [approved live eval](evals/README.md).
- Every bug fix gets a regression test; every behaviour change gets an eval case.
- Update `docs/runbook.md` when behaviour or dependencies change. The AI governance team must approve it before go-live.
- Replace the `# TODO: pin exact version` for `google-adk` in `pyproject.toml`, and say so in the PR when adding dependencies.
- The required `coverage` check enforces the 80% starter mark in `evals/thresholds.yaml`; `quality` runs Ruff, its complexity check, and ty.
- The `evals_no_regression` job in `.github/workflows/agent-checks.yml` is still a failing stub. The comparator is not wired to live evaluations; see the [eval guide](evals/README.md). Workflow changes need CODEOWNERS review.
- Keep PRs under about 150 changed lines. `AGENTS.md` is the instruction file for your coding agent; keep it accurate.

### 7. Prepare for deployment
`agents-cli-manifest.yaml` already targets `agent_runtime`. Check what the project is configured for with:

```bash
agents-cli info
```

Deployment is gated, not self-service. Before deploying:
1. Evals meet the thresholds and show no regression against the baseline.
2. Lint, tests and all required checks pass on the PR, and the PR is reviewed by CODEOWNERS.
3. The mission brief and runbook are complete, and the Product Owner, Architecture, Security and `ai_governance` approvals are recorded.
4. Secrets are in Secret Manager, not in `.env` files or the repo.

Then, with explicit human approval, deploy through the approved pipeline (`agents-cli deploy`; see the `google-agents-cli-deploy` skill for service accounts, secrets, rollback and CI/CD). Never deploy without approval, and make changes through reviewed PRs, not the console.

After deployment, see the `google-agents-cli-observability` skill for tracing and logging, and `google-agents-cli-publish` if the agent is to be registered with Gemini Enterprise.
